Rewrite

Nobody phrases a question the way a document phrases the answer. The question is restated before anything is searched.

Retrieve

Two searches at once — one for meaning, one for exact words — so an invoice number and a paraphrase are both findable.

Rerank

A model reads every candidate and re-orders them against your actual question. Similarity is a guess; this is a judgement.

Deep searchgrep

Search ranks — and whatever falls below the cut is invisible to the answer. This doesn't rank. It reads every document word for word, so if the words are there, they're used.

Judge

A second model checks the answer against its own sources. If it can't decide, it says so — it never guesses at a verdict.

01 The pipeline

A question does not go straight to a language model. It passes through five stages — and each one is shaped by a constraint of running this on one serverless function.

Input Index chunked + embedded
Stage 01 Rewrite sharpen the query
Stage 02 Retrieve vector + BM25
Stage 03 Rerank cross-encoder rescore
Stage 04 Generate answer + citations
Stage 05 Judge grade the answer
Embeddings

One fixed vector(768) column shared by every model, so models swap without a migration. The config fingerprint changes with them and invalidates stale chunks.

Model output

Reasoning models emit a thinking trace. It is stripped before the rewrite is used — otherwise 1,400 characters of deliberation become the search query.

Storage

Neon Postgres with pgvector is both the application database and the vector store. Chroma swaps in for local development behind a single dispatch module.

Configuration

How wide the net is cast is re-read from the database on every request, so tuning it takes effect on the next question with no redeploy.

Runtime

One FastAPI serverless function. The repo directory is read-only and the process freezes the instant a response is sent, so every writable byte goes to the database.

Fail open

A judge that times out is a broken grader, not a bad answer. It reports ungraded — never failed, which would be a confident false claim about your documents.

Benchmarks · long jobs

A background thread would be frozen the moment the response is sent, so the benchmark is sliced: bounded steps, each committing before it returns.

Interface · frontend

Vanilla JavaScript. No framework, no runtime dependencies, two entry points and one stylesheet.

02 By the numbers

56 golden questions over a 27-document corpus, including unanswerable ones — because refusing to answer is a behaviour worth measuring too. Most of the corpus is confusable on purpose: same firm, same vocabulary, different facts, so retrieval has to discriminate rather than recognise a topic. The scored result ships with the app; nobody has to run it.
