Rewrite

Questions are rarely phrased the way a document is. The query is restated before it is searched.

Retrieve

Meaning-based vector search fused with exact keyword matching, so names and IDs are not lost to paraphrase.

Rerank

A language model re-scores the candidates against the question, which catches what similarity alone misses.

Judge

A second model checks the answer against its own sources. When it cannot decide, that is reported as ungraded — never as a failure.

Deep search

Ranking can miss a passage that is plainly there. Turn this on for a question and every document is read word for word as well, so a literal match cannot be ranked out.

01 The pipeline

A question does not go straight to a language model. It passes through five stages — and each one is shaped by a constraint of running this on one serverless function.

Input Index chunked + embedded
Stage 01 Rewrite sharpen the query
Stage 02 Retrieve vector + BM25
Stage 03 Rerank cross-encoder rescore
Stage 04 Generate answer + citations
Stage 05 Judge grade the answer
Embeddings

One fixed vector(768) column shared by every model, so models swap without a migration. The config fingerprint changes with them and invalidates stale chunks.

Model output

Reasoning models emit a thinking trace. It is stripped before the rewrite is used — otherwise 1,400 characters of deliberation become the search query.

Storage

Neon Postgres with pgvector is both the application database and the vector store. Chroma swaps in for local development behind a single dispatch module.

Configuration

How wide the net is cast is re-read from the database on every request, so tuning it takes effect on the next question with no redeploy.

Runtime

One FastAPI serverless function. The repo directory is read-only and the process freezes the instant a response is sent, so every writable byte goes to the database.

Fail open

A judge that times out is a broken grader, not a bad answer. It reports ungraded — never failed, which would be a confident false claim about your documents.

Benchmarks · long jobs

A background thread would be frozen the moment the response is sent, so the benchmark is sliced: bounded steps, each committing before it returns.

Interface · frontend

Vanilla JavaScript. No framework, no runtime dependencies, two entry points and one stylesheet.

03 What makes it non-trivial

Hybrid retrieval, fused

Vector search finds meaning; BM25 finds exact strings. Their rankings are combined by reciprocal rank fusion, so an invoice number and a paraphrased policy are both findable.

Reranking that reads

Retrieval casts a wide net, then a language model re-scores each candidate against the actual question. Embedding distance is a proxy for relevance; this is a judgement.

Deep search, when ranking is not enough

Every retriever ranks, and a passage that ranks just outside the cut is invisible to the answer — the model cannot know what it was not shown. Deep search does not rank: it reads every document word for word and returns every literal match. If the words are in your documents, they reach the answer.

Evaluation that fails open

Answers are scored for faithfulness and relevancy. A judge that times out is a broken grader, not a bad answer, so it reports ungraded — rendering that as a failure would be a confident false claim about your documents.

A benchmark you can run

56 golden questions over a 27-document corpus, including unanswerable ones — because refusing to answer is a behaviour worth measuring too. Most of the corpus is deliberately confusable: same firm, same vocabulary, different facts, so retrieval has to discriminate rather than recognise a topic.
